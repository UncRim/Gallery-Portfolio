01 / Practice

Four kinds of writing, one test

Every building is a kind of content I write, and each piece has to pass the same test: does the reader know what to do next? Click a building to jump to it.

Building 01 · API Reference

Onboarding and reference docs

Documentation for product teams listing on IBM.com marketplaces, AWS and Azure. Task-first, so the answer comes before the parameter table, with examples that look like systems people actually run.

  • Onboarding guides
  • Task guides
  • Error catalogues
Building 02 · Style Guide

Voice, terminology and patterns

Rules that other writers and engineers can apply without asking me. A guide earns its place when a review comment can point to a line in it.

  • Voice and tone
  • Glossary
  • Content patterns
Building 03 · Release Notes

Change communication

What changed, why it matters to the reader, and what they need to do next, in that order. Written so a skim still lands the point.

  • Release notes
  • In-product announcements
  • Migration guides
Building 04 · Microcopy

Interface text

Labels, empty states, errors and onboarding that carry someone through a flow. Small words, tested against the screen they live on.

  • UI copy
  • Error and empty states
  • Onboarding
